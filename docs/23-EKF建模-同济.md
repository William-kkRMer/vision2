# 同济 EKF 怎么建模（把物理问题压进算法）

> 代码：`core/auto_aim/target/target.cpp`（321 行）· `core/auto_aim/tracker/tracker.cpp`
> 本文回答一个问题：**"绕竖轴旋转的整车 + 只能看到 1~2 块板"这个物理现实，是怎么变成 11 维状态 + 一个观测方程的。**

---

## 1. 核心思路：**跟踪"旋转中心"，不跟踪"装甲板"**

⚠️ 最直接的写法是"把每块装甲板当独立目标跟踪" —— 但那样**每块板都有自己的位置/速度**，
    而我们只看到 1~2 块，其余板的约束全丢了。

⭐ 同济的做法：**把整车建模成一个绕竖轴匀速旋转的刚体**，状态里存：
- **旋转中心**（比任何单块板都稳定 —— 它不动，只是平移）
- **一个方位角 `a` + 角速度 `w`**（决定所有板的角度）
- **半径 `r`、半径差 `l`、高度差 `h`**（决定所有板的位置）

⇒ ⭐ **观测任意一块板，都能修正整车的状态** —— 这就是"物理约束进算法"。

---

## 2. 状态向量（11 维）

```
x = [ x, vx, y, vy, z, vz, a, w, r, l, h ]
      └────┬────┘  └────┬────┘  │  │  └─┬─┘
       旋转中心位置     中心速度   │  │   刚体尺寸
                             板0方位角 角速度
```

| 索引 | 符号 | 含义 | 物理角色 |
|---|---|---|---|
| 0,2,4 | `x,y,z` | **旋转中心**位置（世界系，原点=相机） | 整车平移 |
| 1,3,5 | `vx,vy,vz` | 中心速度 | 整车平移 |
| 6 | `a` | **0 号装甲板的方位角** | 整车旋转相位 |
| 7 | `w` | **角速度**（小陀螺转速） | 整车旋转 |
| 8 | `r` | 半径（短半径） | 刚体尺寸 |
| 9 | `l` | `r2 - r1`（长轴与短轴半径差） | ⭐ **矩形车身**的物理事实 |
| 10 | `h` | `z2 - z1`（前后板与侧板的高度差） | ⭐ 同上 |

⭐ **`l` / `h` 只在 `armor_num_ == 4`（标准步兵）时才用**（`h_armor_xyz` 里 `use_l_h = (armor_num_ == 4) && (id == 1 || id == 3)`）：
- 4 块板：`id 0,2` 在半径 `r`、`id 1,3` 在半径 `r+l`（**矩形**）
- 3 块板（前哨站/基地）：三块等半径（**等边三角形**）
- 2 块板（平衡步兵）：前后两块，`l`/`h` 不参与

## 3. 运动模型（`predict`）

### 3.1 状态转移 `F：匀速直线 + 匀速旋转`

```cpp
// target.cpp:79-91
x' = x + vx·dt      y' = y + vy·dt      z' = z + vz·dt
a' = a + w·dt                            ← ⭐ 匀速旋转
vx,vy,vz,w,r,l,h 保持                   ← 常值
```

### 3.2 过程噪声 `Q`：分段白噪声（Piecewise White Noise）

```cpp
// target.cpp:96-121
if (name == outpost) { v1 = 10;  v2 = 0.1; }   // 前哨站：几乎不动、转速慢
else                 { v1 = 100; v2 = 400; }   // 其它：可能突然加速/变速旋转
a = dt⁴/4 ; b = dt³/2 ; c = dt²
Q 的对角块 = [[a·v, b·v], [b·v, c·v]]          // 位置-速度耦合（标准模型）
```

⭐⭐ **关键：`r` / `l` / `h` 的 Q 是【全零】**（第 9,10,11 行全 0）
```
⇒ 它们是【刚体常数】，物理上不会突变 ⇒ 不给过程噪声
⇒ 只能被测量慢慢修正，不会自己漂走
```
⭐ **这就是把"车身尺寸是常数"这条物理知识写进算法的方式。**

### 3.3 角度环绕：`x_add` 钩子

```cpp
// target.cpp:43-47
auto x_add = [](a, b) { c = a+b; c[6] = limit_rad(c[6]); return c; };
```
⚠️ 普通卡尔曼里 `x + Δx` 是向量加法，但 **角度是环上的量**：
`179° + 5° = 184°` 应变成 `-176°`，否则会"绕大圈"。
⭐ **→ 把非欧几里得空间的距离定义注入滤波器**（EKF 基类用 `x_add` 钩子实现）。

### 3.4 ⭐⭐ 前哨站转速钳位（一条纯物理先验）

```cpp
// target.cpp:131-133
if (convergened() && name == outpost && std::abs(w) > 2)
  w = (w > 0) ? 2.51 : -2.51;
```
⭐ **前哨站的转子转速是【机械固定】的（≈2.51 rad/s）** ⇒ 一旦收敛，就**不准它跑偏**。
⚠️ 这是典型的"用物理常识纠正滤波"。

## 4. 观测模型（`h`）：从状态**重建**某块装甲板

### 4.1 观测量是什么（4 维，**球坐标 + 朝向**）

```cpp
// target.cpp:218-220
z = { armor.ypd_in_world[0],   // yaw      ← 从相机看装甲板的方位角
      armor.ypd_in_world[1],   // pitch    ← 仰角
      armor.ypd_in_world[2],   // distance ← 直线距离
      armor.ypr_in_world[0] }  // 装甲板自身朝向
```
⭐ **不是直接用 `xyz`（笛卡尔），而是 `yaw/pitch/distance`（球坐标）**
- ⭐ **好处**：yaw/pitch 的噪声**各向同性**（旋转对称），且**距离误差与角度误差解耦**
- ⚠️ 笛卡尔下，远距离时 x/y 误差强相关、且非线性更重

### 4.2 观测函数 `h(x, id)`：**刚体约束在这里**

```cpp
// target.cpp:267-278  h_armor_xyz
angle   = limit_rad(x[6] + id · 2π/armor_num_)   ← ⭐ 板只在【这一个】角度上
use_l_h = (armor_num_ == 4) && (id == 1 || id == 3)
r_eff   = use_l_h ? (x[8] + x[9])  : x[8]        ← ⭐ 半径只有两个取值
z_eff   = use_l_h ? (x[4] + x[10]) : x[4]
armor_x = x[0] - r_eff·cos(angle)
armor_y = x[2] - r_eff·sin(angle)
armor_z = z_eff
```
⭐ **这条式子就是整个建模的灵魂**：
> **"任意一块装甲板，必须位于以旋转中心为圆心、半径 r（或 r+l）的圆上，
>   角度为 `a + id·2π/N`。"**

⇒ ⭐ **观测 1 块板时，其余 N−1 块板的"应该在哪"就被这条约束确定了**；
   而 `r` / `w` 要**靠它转起来之后的轨迹** + 先验才能收敛（单帧不可观）。

### 4.3 完整 `h`：再转成球坐标 + 加上板朝向

```cpp
// target.cpp:202-207
h(x) = { ypd[0], ypd[1], ypd[2],  limit_rad(x[6] + id·2π/N) }
         └─ xyz2ypd(h_armor_xyz(x,id)) ─┘   └─ 板0角度 + 偏移 ─┘
```

### 4.4 雅可比 `H`：链式法则，解析求导

```cpp
// target.cpp:280-317
H_armor_xyza = [ 对中心的偏导(单位阵), 对 a/w/r/l/h 的偏导 ]   // 11 列
  dx_da =  r·sin(angle)      dy_da = -r·cos(angle)     ← 角度变化引起的位移
  dx_dr = -cos(angle)        dy_dr = -sin(angle)       ← 半径变化引起的位移
  dx_dl = use_l_h ? -cos : 0                           ← 只有前后板受 l 影响
  dz_dh = use_l_h ? 1 : 0
H_armor_ypd   = xyz2ypd_jacobian(armor_xyz)            // 球坐标偏导（见 math_tools.cpp）
H = H_armor_ypda · H_armor_xyza                        // ⭐ 链式法则
```
⭐ **全部解析求导，没有数值差分** ⇒ 快且准。

## 5. ⭐⭐ 测量噪声 `R` 是**几何相关**的（这一条最见功力）

```cpp
// target.cpp:192-196
auto center_yaw   = atan2(armor.y, armor.x);          // 相机→装甲板的方位
auto delta_angle  = limit_rad(armor.ypr[0] - center_yaw);

R_dig = {
  4e-3,                                  // yaw      ← 常数
  4e-3,                                  // pitch    ← 常数
  log(|delta_angle| + 1) + 1,            // ⭐ distance：**"侧对"时不可信**
  log(|armor.ypd_in_world[2]| + 1)/200 + 9e-2   // ⭐ 板朝向：**距离远时不可信**
                                                  //    ⚠️ ypd[2] 是【距离】不是仰角
};
```

| 分量 | 依赖 | 物理含义 |
|---|---|---|
| ⭐ `R[2]`（距离） | **板朝向与视线夹角** `delta_angle` | **正对相机** ⇒ 距离准（R≈1）；**侧对/斜看** ⇒ 距离差（R 指数增长） |
| ⭐ `R[3]`（板朝向） | **距离 `distance`** | **距离越远**，板在图上越小 ⇒ 朝向估计越差（`ypd[2]` 是距离） |

⚠️ 普通 EKF 里 `R` 是个常数对角阵。⭐ **同济把它做成"当前几何的函数"** ——
    这就是"**实际问题融入算法**"最直接的例子：**同一块板，看得正 vs 看得斜，可信度本来就不同**。

## 6. 数据关联：**观测到的是哪块板？**

```cpp
// target.cpp:140-169
1) 用【上一时刻的状态】推出 N 块板的假设位置  ← armor_xyza_list()
2) 按 distance 排序，只查最近的 3 个
3) 对每个假设算 angle_error：
       |limit_rad(实测板朝向 - 假设板朝向)| + |limit_rad(实测方位 - 假设方位)|
4) 取 angle_error 最小的假设，得到 id
5) update_ypda(armor, id) —— 用这个 id 去算 H 和 h
```
⭐ **两个误差都算**（朝向 + 方位）⇒ 更 robust：
   只有"方位对"可能是另一块板；"朝向也对"才确认。

### ⚠️ 6.1 这里有个**越界隐患**（上游原版就有，本项目沿用）

```cpp
std::vector<...> xyza_i_list;      // 长度 = armor_num_（可能是 2 或 3）
for (int i = 0; i < armor_num_; i++) xyza_i_list.push_back(...);
...
for (int i = 0; i < 3; i++) {      // ⚠️ 固定 3 次！
  const auto & xyza = xyza_i_list[i].first;   // ⚠️ armor_num_==2 时 i==2 越界
```
⚠️ **平衡步兵（`armor_num_ = 2`）会读到 `xyza_i_list[2]`（UB）** ⇒
   可能选到错误的 `id` ⇒ 观测方程用错板 ⇒ **跟踪跑偏**。
⭐ 建议改成 `for (int i = 0; i < std::min<int>(3, armor_num_); i++)`。
📌 **未改**（属于同济算法本身，改动需确认；已记录在本文）。

## 7. 物理护栏：怎么判断"算崩了"

```cpp
// target.cpp:241-250  diverged()
r_ok = 0.05 < x[8] < 0.5                    // ⭐ 半径必须像辆机器人
l_ok = 0.05 < x[8] + x[9] < 0.5             // ⭐ 长半径也要合理
⇒ 任一不满足 = 发散 ⇒ Tracker 把状态机打回 lost
```
```cpp
// tracker.cpp  NIS 守卫
if (最近 NIS 失败数 ≥ 0.4 × window_size) ⇒ "Bad Converge" ⇒ 回 lost
```
⭐⭐ **注意这两条护栏都是"物理/统计合理性检查"，不是数学推导出来的** ——
    **算法自己不知道自己崩了，得靠"这辆车的半径不可能是 3 米"来判定。**

## 8. 初始化：**从 1 块板 + 已知半径反推中心**

```cpp
// target.cpp:29-40
center = armor_pos + r·(cos(yaw), sin(yaw))       // ⭐ 用【已知半径】反推旋转中心
x0 = { center_x, 0, center_y, 0, center_z, 0, yaw, 0, r, 0, 0 }
        └── 速度全 0 ──┘        └ 相位=yaw ┘ └转速0┘ └半径=r┘
```
⚠️ **只看到一块板时，中心和半径是【不可观】的** ⇒ **必须靠先验半径**：

| 兵种 | `r` | `armor_num` | `P0` 关键项 |
|---|---|---|---|
| 标准步兵（4 板） | **0.2** | 4 | `w`:100（转速完全未知）、`r`:1（半径也放很大） |
| 平衡步兵（2 板） | **0.2** | 2 | 同上 |
| 前哨站（3 板） | **0.2765** | 3 | ⭐ `r`:1e-4（半径已知！）、`l`/`h`:0（固定）、`vz`:**81** |
| 基地（3 板） | **0.3205** | 3 | ⭐ `r`:1e-4、`l`/`h`:0、`vz`:**64** |

⭐ **`P0` 也是物理先验**：前哨站半径是机械尺寸 ⇒ 几乎不给不确定度；
   步兵的半径/转速是"什么车都可能" ⇒ 给很大，让测量去收敛。

## 9. 模型怎么被用来"打中"

```cpp
// mpc.cpp
auto traj     = trajectory_->solve(bullet_speed, dist, z);  // 弹道 → 飞行时间 t_fly
target.predict(t_fly);                                     // ⭐ 推算 t_fly 后的状态
// 然后 armor_xyza_list() 给出【所有板】的未来位置 → 选最近的一块 → MPC 解云台轨迹
```
⭐ **因为是"整车模型"，所以能预测任意一块板的未来位置** ——
   而不是只能预测"上次看到的那块"。

## 11. 一句话总结

⭐⭐ **同济的 EKF 不是"套一个卡尔曼公式"，而是把三件事编进了模型：**
1. **几何约束**（板在圆上、等间隔、矩形车身）→ 写进观测函数 `h`
2. **物理先验**（尺寸不变、转速固定、半径范围）→ 写进 `Q`、`P0`、`diverged()`
3. **测量质量随几何变化**（正对 vs 侧对、仰角高低）→ 写进 `R`

⇒ ⭐ **观测 1 块板，就能推断出整车的中心/半径/转速** —— 这才是"用算法解决实际问题"的样子。
